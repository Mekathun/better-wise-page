# 拼音搜索 Pinyin Matching

一句话：搜索除了认字面，还认全拼、音节边界、首字母，全是运行时现算，没给条目建索引表。

`注入点 extension/search.js:L118 pyMap() · 数据 extension/pinyin-data.js 一整行`

## 它做什么

| 输入 | 命中方式 | 分值 |
|---|---|---|
| `maths` | 字面（词边界 or 子串） | 3 |
| `shuxue` / `sx`（≤3 字符） | 音节表 `_syl` 或首字母串 `_iniS` 的空格边界 | 2 |
| `shuxuejia`（>3 字符） | 全拼串 `_py` / 首字母串 `_ini` 子串 | 2 |
| 打错一个字母（≥4 字符） | `nearIncludes` 容错，仅在全无结果时兜底 | 1 |

`pinyin-data.js` 是 `window.__WT_PINYIN = {"a":"啊嗄錒…","ai":"伌僾…",…}`，音节→该音节所有汉字。`pyMap()` L118 反着建成 字→音节 的表，第一次用才建。

## 关键函数

| 函数 | 行 | 作用 |
|---|---|---|
| `pyMap()` | L118 | 反转 `__WT_PINYIN` 成 `PY_MAP`，惰性、只建一次 |
| `pinyinOf(text)` | L128 | 逐字转拼音，返回 `{full, syl, iniS, ini}` 四路串 |
| `entryPinyin(e)` | L147 | 给条目算并缓存 `_py/_syl/_iniS/_ini`，输入取 `[title,body,cls,aliases]` |
| `matchToken(e,t)` | L1152 | 字面 3 分 / 拼音 2 分 / 0 分淘汰 |
| `nearToken(e,t)` | L1170 | 4 字符以上才做容错 |
| `nearIncludes` | L157 | 滑动窗口 + 1 处编辑距离（长短差 ≤1） |

## 约束与坑
- 只取 `[title, body, cls, aliases].join(' ').slice(0, 900)`（`entryPinyin` L147）：正文很长的条目后半段不参与拼音匹配。
- `pinyinOf` 里 `count > 420` 就 break（L128）：超过 420 个汉字的部分直接丢。
- 拉丁字母和数字原样小写进四路串（同函数），所以中英混排能连续命中，但也会让 `_py` 里混进英文单词。
- 3 字符是硬分界（`matchToken` L1152）：≤3 走空格边界匹配，>3 走子串。改这个阈值会同时影响误命中率和短查询召回。
- `_syl` 与 `_iniS` 前后各留一个空格（L128 返回处），就是为了 `(^| )x( |$)` 这种边界正则能直接用。
- 容错只在「一个词、≥4 字符、前面一条都没命中」时跑，而且总预算 60ms（`localSearch` L1297 循环里 `Date.now() - t0 > 60` 就 break）。
- 拼音命中永远只有 2 分，压不过字面 3 分，也压不过标题完全命中的 120（`scoreEntry` L1255）。想让拼音更靠前得改分值，不是改数据。
- 每次搜索都会给候选条目 `entryPinyin`，结果缓存在条目对象上（`e._py !== undefined` 早退），索引重爬后缓存随之失效。
