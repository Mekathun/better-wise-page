# 怎么用这个库

这份是给 AI 看的操作手册。人只需要知道：**用 Obsidian 打开 `D:\DSH\Better_WiSE\vault`**，其余照旧。

---

## 一、库分成两层，别搞混

| 层 | 位置 | 谁写 | 被覆盖怎么办 |
|---|---|---|---|
| **生成层** | `300-轮次记录/`、`000-入口/L0-钉住上下文.md`、`700-归档/PROGRESS.md`、`600-素材与样本/原文/`、`600-素材与样本/00-原文索引.md`、`300-轮次记录/00-轮次索引.md` | `scripts/sync.py` | 会被重建。要改就去改源头（`PROGRESS.md` 或 `docs/`），别改这里 |
| **手写层** | `000-入口/` 其余、`100-`、`200-`、`400-`、`500-`、`600-素材与样本/00-素材地图.md`、`900-` | 人 / AI | 只有你写，没人覆盖 |

生成文件第一行都带 `<!-- generated: sync.py` 标记，`check.py` 靠它认人。手写层里出现这个标记会被当成「生成层被动」报出来。

---

## 二、四个动作

### 1. 开工（ingest）
读的顺序，一级不够才往下：

1. [[000-入口/00-首页]] —— 250 tok，知道这是什么、现在什么状态
2. [[000-入口/L0-钉住上下文]] —— 2.4k tok，goal / 下一步 / 硬约束
3. 按首页那张**触发词表**取 1–2 篇专题卡
4. 要动某段代码时才打开源码，用卡里给的 `文件:行号` 定点读

一次会话读满 **5 篇**就停手，回去干活。读第六篇通常说明路由错了。

### 2. 干活中（query）
- 想知道「以前怎么解决过」→ [[300-轮次记录/00-轮次索引]] 的**一句话**列扫一遍，别点开
- 想知道「为什么当年这么定」→ `500-决策/`
- 想知道「这段代码在哪」→ `200-*` 的函数表

### 3. 收尾（file-back）
干完活，**只有当出现了新结论**才写。写哪里：

| 出现了什么 | 写到 |
|---|---|
| 一个新的界面事实、坑、函数位置 | 改对应的 `200-*` / `400-*` 那一篇（别新建） |
| 一个以后会被人问「当初为什么」的选择 | `500-决策/` 新建，编号顺延 |
| 这一轮做了什么 | 什么都不用写 —— 往 `PROGRESS.md` 加一节，跑 `sync.py`，自动出一篇 |
| 一条待办 | `000-入口/待办-全局.md` |

新建命名：`NNN-短标题.md`，NNN 三位数，标题控制在 20 字内。

### 4. 体检（lint）
```bash
cd /d/DSH/Better_WiSE
python vault/scripts/sync.py           # 重建生成层（改了 PROGRESS.md 或 docs/ 之后跑）
python vault/scripts/check.py --quiet  # 断链 / 缺属性 / 孤儿 / 超预算 / 生成层被动 / 敏感串
```
`check.py` 退出码非 0 说明有问题，先修再交。

## 三、frontmatter 规范

每篇开头必须有，`check.py` 会查：

```yaml
---
type: card | map | router | protocol | project | decision | todo | round | index | context | source-doc | template
topic: 一句话主题
source: extension/home.js      # 可选，来源文件
lines: 1124-1160               # 可选，行号区间
date: 2026-11-15
tokens: ~1200
status: done | stub
---
```

`type` 是筛选用：想让 AI 只看界面卡，就 `grep -l "^type: card" -r vault/200-界面`。

## 四、token 预算

| 文件 | 上限 | 超了怎么办 |
|---|---|---|
| `000-入口/00-首页.md` | 1500 | 砍表格，砍不掉就挪到 L1 |
| `000-入口/L0-钉住上下文.md` | 3000 | 改 `sync.py` 里的 `L0_CAP` |
| `000-入口/L1-总览地图.md` | 2600 | 同上思路，挪到专题卡 |
| 专题卡（`100/200/400`） | 9000 硬顶 | 单卡 **2500** 就该拆成两篇 |
| `500-决策` 单篇 | 1500 | 决策只写结论和理由，不写过程 |

`check.py` 用的是粗估：CJK 一字算 1 tok，ASCII 词算 1，其余字符 /4。跟真实分词有误差，够用。

## 五、什么不要进这个库

- **凭据**。账号、密码、cookie、BDUSS、token 一律不落盘。`check.py` 有一组正则专门抓这个，抓到了会报「敏感串」。
- **大二进制**。`design/`（101 MB）、`sessions/`（37 MB）、`tools/`（4.2 GB）都留在原地，库里只写「它在哪、里面是什么」。
- **过程流水账**。那种东西属于 `PROGRESS.md`，由 `sync.py` 转成轮次笔记，不要在手写层再抄一遍。

---

## 六、扩展这个库

加一个新专题（比如「Safari 适配」）：

1. 在对应目录建 `NNN-标题.md`，照 [[900-模板/知识卡模板]]
2. 在 [[000-入口/00-首页]] 的触发词表加一行（不加就是孤儿，`check.py` 会报）
3. 跑 `check.py`
