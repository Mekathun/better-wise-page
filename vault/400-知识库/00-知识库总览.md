# 知识库总览

一句话：这里只放「从代码里读出来、以后还会再问」的结论。过程在 `PROGRESS.md`，代码本身在 `extension/`。

## 这库收什么，不收什么

| 收 | 例 | 落到哪 |
|---|---|---|
| 站点自己的规律：DOM、类名、URL、接口 | `table.timetable[data-timetable]`、`/calendar/ajax/full` | 01 |
| 我们注入的手段与踩过的坑 | `#wt-boot-chrome`、60px 空白条 | 02 |
| 一次搞对就不用再想的事 | 三段注入、扩展 ID、出包 | 03 |
| 库本身的检索协议 | 分层、触发词、预算 | 04 |

不收的三样：凭据（`check.py:34-39` 有正则抓）、大二进制（`design/`、`tools/` 只写路径不搬）、过程流水账（那是 `PROGRESS.md` 的活，`sync.py` 已转成轮次笔记）。

判断标准是「这句话能不能从代码重算」：能，就写结论加一个 `文件:行号`；不能（取舍、教训、为什么这么改），才值得展开。

## 怎么加一张新卡

1. 本目录建 `NNN-标题.md`，frontmatter 照本页和 01–04 抄：`type/topic/source/lines/date/tokens/status`
2. 上面那张表加一行，并且从本页链过去。不链就是孤儿，`check.py:112-117` 会报
3. 跑 `cd /d/DSH/Better_WiSE && python vault/scripts/check.py --quiet`

三条自检：断言有没有 `文件:行号`；代码块是否 ≤8 行；`tokens` 是否还在预算里（专题卡硬顶 9000，但 2500 就该拆成两篇）。
