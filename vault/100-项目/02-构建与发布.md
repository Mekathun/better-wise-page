# 构建与发布

```bash
cd /d/DSH/Better_WiSE/extension
node build-extension.mjs
```

产物自动落到**仓库根目录**，文件名跟 `manifest.json` 的 `version` 走：`Better_WiSE_v<version>.crx` 和 `.zip`。

---

## 脚本干的六件事

| # | 动作 | 细节 |
|---|---|---|
| 1 | 读或生成密钥 | `../build/wesley-cards-extension-key.pem`，没有就现场生成 2048 位 RSA |
| 2 | 写 `manifest.key` | 公钥 SPKI 的 base64。有了它扩展 ID 才固定，换电脑也一样 |
| 3 | 算扩展 ID | `sha256(spki)` 取前 32 个 hex，每一位按 `a + 值` 映射成字母 |
| 4 | 打 zip | 用 `python -c` 调 `zipfile`，跳过 `*.pem`、`*.zip`、`*.crx`、`build-extension.mjs`、`make-icons.py` |
| 5 | 出 CRX3 | Edge 无头 `--pack-extension=<dir> --pack-extension-key=<pem>`，临时 profile 跑完即弃 |
| 6 | 复制到根目录 | 读 `manifest.version` 当版本号，复制 crx + zip，删掉中间产物 |

最后打印 `EXTENSION_ID: ecdedhcfflmobjlbcfanknhcpnnchefi`。这个 ID **必须一直不变**，变了等于换了一个扩展，用户得重装。

Edge 的路径在脚本里写死：
`C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe`

---

## 版本规则

1. 改 `extension/manifest.json` 的 `version`，末位 +1（`0.1.2.17` → `0.1.2.18`）
2. **同时**改 `extension/options.js` 里那个兜底版本串 —— 两处不同步，设置面板会显示错版本
3. `node build-extension.mjs`
4. 产物在根目录，名字自带版本号

历史上有过「只改一处」的坑，见 [[300-轮次记录/00-轮次索引]] 里 0.1.2.6 那轮。

## 打包脚本的一个副作用

`node build-extension.mjs` 不检查目标是否存在，同名产物直接覆盖。版本号没 +1 就跑一次，根目录那份 `Better_WiSE_v<版本>.crx/.zip` 会被悄悄换掉，文件大小和 mtime 全变，事后分不清哪份是什么时候出的。

2026-11-15 20:39 就碰上一次：为了核对扩展 ID 跑了打包脚本，`Better_WiSE_v0.1.2.17.crx` 从 598,567 B 变成 601,001 B。内容验过，21 个文件与 `extension/` 当前源码逐字节一致，没有坏东西；但那次覆盖意味着 20:29 那份没留底。

所以：**只为了看 `EXTENSION_ID`，别跑打包**。那段公钥算法在 `build-extension.mjs` 里，单独算一遍就行；真要出包，先 +1 末位版本。
